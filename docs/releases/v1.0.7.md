# Oberiz v1.0.7 — Persistent daily search scheduling

- Settings → Automation now offers 1–24 search cycles per local calendar day instead of a fixed interval. Existing interval settings derive the initial daily count: 360 minutes becomes four cycles per day.
- Each day receives one random execution time in the middle half of each daily window, keeping cycles spaced. Two cycles use one window in each half of the day; they do not run at fixed 12-hour intervals.
- The default-on **Keep schedule after restart** checkbox preserves the saved plan through restarts and power outages. Turning it off regenerates the plan after restarting, without launching an immediate startup search.
- Execution slots are consumed in SQLite before network work. Missed cycles are not replayed in a burst; a partially elapsed day or a long-running cycle may execute fewer cycles than configured.
- Manual and on-add searches remain additional to the daily plan. A cycle may query multiple indexers and targets; the daily count is not a total HTTP-request limit.
- Changing the daily count regenerates the plan. Day boundaries follow the server timezone, including daylight-saving changes. No database migration is required.
- Search queries, sessions/cookies, matching, quality rules, pack/episode selection and download routing are unchanged.
- Random timing does not conceal automation or override tracker rules. Do not enable trackers that prohibit automated use.
- Regression tests cover daily counts and spacing, persisted plans across database reopen, single-use slots, missed days, setting changes and plan regeneration. The interface is translated into six languages.
- Publishing this release does not install updates or restart remote services.
