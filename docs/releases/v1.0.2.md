# Oberiz v1.0.2

## Almacenamiento simplificado

- Inventario seleccionable: Cinetta mediante la API pública o escaneo local de
  solo lectura. Se muestra la fecha del último informe recibido.
- Sin inventario Cinetta reciente (24 horas), las nuevas adquisiciones quedan
  en espera. Se conserva el inventario anterior y no se activa el escaneo local.
- Retiradas la importación directa, copias, hardlinks, movimientos, carpetas de
  reseed y conexiones/credenciales SMB gestionadas por Oberiz.
- Los destinos de descarga se configuran en las categorías de qBittorrent.

## Renombrado opcional y recuperación

- Renombrado mediante qBittorrent configurable en Ajustes y **desactivado por
  defecto**, incluso al actualizar desde instalaciones con renombrado antiguo activo.
- Diario persistente antes de modificar nombres, verificación de cada paso y
  reintentos tras desconexiones sin repetir cambios ya confirmados.
- Comprobación del destino físico mediante la API de qBittorrent. Si la consulta
  no está disponible o el destino está ocupado, se bloquea el renombrado.
- Archivo `.torrent`, hash, destino y correspondencias de nombres en SQLite,
  incluidos en las copias de seguridad de la base de datos.
- Recuperación v1/híbrida detenida, con confirmación y recheck; nunca se envían
  órdenes de start/resume automáticamente. Revisar selección de archivos y
  preferencias en qBittorrent antes de reanudar.
- Las políticas de compartición conservan los archivos descargados. También se
  rechazan las peticiones manuales de borrado de datos.

## Actualización y límites

- Copia SQLite coherente antes de aplicar la migración 0022 sobre una instalación
  existente. Se conserva el historial y se retiran las antiguas credenciales SMB.
- Los antiguos registros y `.torrent` externos no se convierten automáticamente:
  requieren recuperación manual. La recuperación de torrents v2 puros es manual.
- qBittorrent no ofrece renombrado atómico sin reemplazo. No ejecutar otros
  organizadores simultáneamente sobre los mismos destinos; la consulta de
  directorios tampoco garantiza detectar entradas ocultas no expuestas por su API.
- Cinetta debe tener URL/clave de Oberiz y el envío de inventario activados. La
  instalación/publicación de Oberiz no configura ni modifica Cinetta o el NAS.
- Docker: el montaje de medios pasa a ser opcional y de solo lectura para el
  escaneo local. Cinetta por API no necesita montar la biblioteca.

## Verificación

Pruebas automáticas del backend y migración, compilación y regresiones del
frontend en seis idiomas, y las 11 pruebas del emisor JavaScript existente de
Cinetta. Prueba con qBittorrent real v5.2.3 en perfil aislado y torrent sintético:
renombrado, hash conservado al exportar, recuperación detenida, recheck al 100 %
y protección del destino ocupado mediante el código Rust de Oberiz.

No se ha accedido al NAS ni se han modificado torrents del usuario.
