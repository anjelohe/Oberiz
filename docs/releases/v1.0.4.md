# Oberiz v1.0.4 — Missing content reports and a refreshed interface

## Library

- Independent reports for missing episodes and incomplete movie collections, across the library or for an individual title.
- Cinetta inventory access using the `library:read` permission and TMDB metadata. Only valid release dates on or before today (UTC) are included.
- Opening a saved report does not start a refresh. Jobs are persistent, paginated, and idempotent.
- Reports do not create requests, enable monitoring, or start downloads. They do not access NAS files.
- Incomplete inventories are marked as provisional: they do not establish that a file is physically missing.
- Connection settings are available in Settings. Public API access to reports is disabled by default.

## Appearance

- The Middle theme is the default for new installations, preserving existing selections. The Oberiz symbol is now used as the favicon.
- Consistent SVG icons, sidebar navigation, and search styling. The Add content button uses white text and a circled plus icon.
- Borderless dashboard panels across all themes, with subtle orange poster borders in Middle.
- Green active navigation in Light and Dark themes, and orange in Middle.
- Matching heights for Recent activity and Upcoming episodes, with System status aligned to the bottom on desktop.
- Three recent downloads at viewport widths up to 1920 pixels and four above that, with consistently sized panel actions.
- Consistent report controls, filters, status indicators, and checkboxes.

## Security and qBittorrent connectivity

- Reused qBittorrent HTTP client and session cookie, coordinated session renewal, hash-filtered queries, and non-overlapping polling. These changes do not modify torrents or preferences.
- No automatic external redirects, with stricter IPv4/IPv6 filtering. Supported www aliases and download subdomains use validated, pinned public addresses. Login redirects are validated and bounded, without arbitrary port changes or HTTPS downgrades. Explicitly configured local indexers remain supported.
- Streamed backup uploads: one at a time, up to 512 MiB, with a five-minute timeout. Restoring a backup preserves the current password, keys, and connections.
- Refreshes retain up to three previous terminal reports per scope. New jobs are subject to a 200-record threshold and a 64 MiB storage threshold, with a 16 MiB result limit, two concurrent jobs, 128 retry keys per active job, and seven-day retry-key expiration.
- Cache eviction preserves the current scope's latest valid report. An unconfigured connection does not clear the global cache. Metadata is processed incrementally without preloading every season. Multi-episode ranges use overflow-safe arithmetic.
- Indexer catalogs support original identifiers containing uppercase letters. Invalid definitions are skipped without discarding the entire catalog.
- Bounded, expiring login-attempt tracking; catalog download and extraction limits; serialized catalog synchronization; and URL error messages with secrets redacted.
- Windows system tools are invoked from System32, with CI permissions scoped per job.
- Initial password setup over the network remains supported.

## Data upgrade

The additive `0023_missing_reports.sql` migration preserves inventory and history.
The integration requires a compatible Cinetta inventory endpoint; see the
[integration contract and configuration](https://github.com/anjelohe/Oberiz/blob/main/docs/Oberiz_Faltantes_Contrato.md).

Windows, Linux, and Docker builds are generated by this tag's release workflow.
Existing local installations are not updated or restarted automatically.
