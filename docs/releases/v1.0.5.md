# Oberiz v1.0.5 — Cached metadata and incremental inventory

## Faster missing-content reports

- Persistent SQLite cache for the compact TMDB metadata needed by reports. Repeated checks reuse valid metadata instead of querying the provider again.
- Configurable intervals in Settings → Missing content reports: metadata refresh (7 days by default), finished/canceled series refresh (90 days), inventory checks (1 hour), and full inventory reconciliation (7 days).
- Metadata expires on demand, not through an automatic bulk download. Release dates are evaluated against the current date and newly received inventory is used immediately.
- Shared cache misses avoid duplicate provider calls. Storage is bounded to 20,000 entries and 128 MiB of cached JSON with least-recently-used eviction.
- If the provider fails, cached data no older than one year may be reused with a `metadata_stale` warning. Failed responses do not extend freshness.

## Incremental Cinetta integration

- The existing authenticated status endpoint advertises synchronization capabilities, accepted revision, and configured sender intervals. No additional connection or API key is required.
- Optional revision-based inventory submissions support changed paths and lightweight heartbeats. Revision mismatches return 409 without applying changes; a full reconciliation recovers the connection.
- Existing collection membership and release dates from Cinetta can seed the metadata cache. New members are merged without resetting cache freshness or replacing newer provider fields.
- Existing senders remain compatible with additive full inventory submissions. **Incremental transmission requires the updated Cinetta sender**, distributed separately from Oberiz.
- Offline/empty-root safeguards remain in place. Inventory changes do not delete NAS files or issue torrent commands.

## More complete indexer searches

- Search both the original title and its punctuation-normalized spelling, even when the first query already returns results.
- Merge and deduplicate releases before applying existing quality profiles and title/year checks. Accents, years, and episode markers are preserved.
- Additional queries are paced; a failed additional query does not discard existing results. Unchanged spellings do not generate an extra request.
- Five regression tests cover combined results, deduplication, unchanged titles, query failures, and year fallback.

## Upgrade and verification

- Updated ZIP handling to zip 9.0.4 after new dependency advisories. Indexer installation still uses bounded manual entry reads and does not apply archive permissions or extract archive symlinks.

- Additive migration `0025_metadata_cache.sql`; existing library data, requests, history, and recovery records are preserved.
- Backend regression tests cover cache expiry/reuse, finished-series intervals, stale fallback, concurrent misses, settings validation, revision mismatch, heartbeats, and collection metadata.
- Frontend translations, regression suites, and production build verified locally. See the [design and configuration guide](https://github.com/anjelohe/Oberiz/blob/main/docs/Oberiz_Incremental_Inventory.md) for defaults and limitations.
- Initial cache population can still take time. Report calculations still walk the selected scope; incremental transport does not eliminate all local work or sender filesystem checks.
- Publishing this release does not update installed services or restart qBittorrent automatically.
